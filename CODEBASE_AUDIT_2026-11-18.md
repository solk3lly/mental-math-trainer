# Mental Math Trainer codebase audit

**Reviewed 18 November 2026** against `main` at `f5207241a92d4e8dc7dbbbe2345f7708305fa255`, including existing working-tree edits to `README.md`, `tests/themes.test.cjs`, and `utils/themes.js`. The web audit covers the current tree. Android findings refer to the separate, published 1.0.5 source snapshot. [Previous web audit](CODEBASE_AUDIT.md) · [Android 1.0.5 release assets](https://github.com/solk3lly/mental-math-trainer/releases/expanded_assets/android-v1.0.5)

The most consequential findings are loss of newer queued answers when an older reset response arrives late, an Android updater that rejects the repository’s current URLs, and cloud compatibility breaks between the current migrations and Android 1.0.5. This report records **16 confirmed findings**. Hosted rollout status, production database behavior, and rendered UI behavior remain unverified.

## Confirmed findings

### 1. An older reset response can erase newer queued answers · High

If a reset response is delayed while another device commits a subsequent reset, a trainer tab on the first device can read the newer generation and queue answers before the older response arrives. Round start reads the server generation without the browser reset lock, and the manual buffer writes to IndexedDB before acquiring its cloud-write lock. The older response overwrites the newer generation in memory, filters the buffers, and deletes queued rows whose generation differs from the older response. An in-memory storage check with a mocked backend observed a queued generation `2` answer disappear when a delayed generation `1` response resolved. The database’s generation check cannot recover a locally deleted answer. Keep observed generations monotonic and remove only rows older than the completed reset. [Round start](utils/useAccountProgressRound.js#L17-L28) · [Checkpoint](utils/progressLogs.js#L475-L480) · [Reset coordination](utils/progressWriteCoordinator.js#L69-L82) · [Durable cleanup](utils/progressStorage.js#L411-L420)

### 2. The published Android updater rejects the current release endpoints · High

Android 1.0.5 still queries `api.github.com/repos/prezvious/mental-math-trainer/releases?per_page=20`. On the audit date that public endpoint returned `301` to `api.github.com/repositories/1159156309/releases?per_page=20`. The native redirect check admits release asset hosts and the original repository’s asset path, so it rejects this API redirect. The release JSON also reports `browser_download_url` under `solk3lly/mental-math-trainer`, which fails the JavaScript asset URL equality check and the native old-owner path check. These are two independent boundaries in the same check flow. Users of the released app need a working distribution route for the first corrected update. Adopt the stable repository identity or current canonical path in the next client, with narrow endpoint checks and the existing signature, package, hash, and version verification. [Current release metadata](https://api.github.com/repos/solk3lly/mental-math-trainer/releases/tags/android-v1.0.5) · [GitHub redirect guidance](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api#follow-redirects) · [Published source](https://github.com/solk3lly/mental-math-trainer/releases/expanded_assets/android-v1.0.5) (`utils/androidUpdates.js:1–15`, `AppUpdaterPlugin.java:117–140`, `UpdatePolicy.java:28–53`)

### 3. The current web migration sequence breaks account sync in Android 1.0.5 · High

On a shared backend, dropping `user_preferences.interface_style` breaks the Android bundle’s preference read and write, including unrelated trainer and appearance fields selected or submitted together. The bundle also omits `reset_generation` in its progress writes. Once the account’s generation advances, the column default `0` cannot satisfy the insert trigger and reopening the same installed app cannot change its payload. The README’s refresh guidance is sufficient only for clients that can load the new web code. Decide how to sequence a compatible Android client and the schema cutover, and document the recovery path for users of the installed bundle. Confirm which migrations are present on the shared service before planning rollout. ### 4. A guest checkpoint failure can leave an ended round locked · Medium

If the guest session opens successfully and an answer checkpoint then fails, Standard and Mixed clear the active round, see `guestSaveErrorRef`, and throw before calling `finishGuestSession`. The failed summary permits leaving the page or starting again. The held session remains in the shared lock registry and recovery, retention, and Clear device history exclude it while the document stays open. Already-saved attempts can remain active and unavailable for import. A successful retry can release the lock. Release the session when leaving the active state even when a write failed, and preserve the summary or already-committed rows for retry. [Standard finalization](pages/index.js#L393-L432) · [Mixed finalization](pages/mixed.js#L297-L326) · [Lock ownership](utils/guestSessionLocks.js#L9-L43) · [Recovery and Clear](utils/progressStorage.js#L215-L229) · [Clear filter](utils/progressStorage.js#L302-L312)

### 5. Import can disappear without importing while reset is in progress · Medium

The Import history button remains enabled while reset is in progress. If an import starts during reset, the write coordinator captures the older browser generation, waits for the reset, then returns without invoking the import callback. The import handler treats that resolution as success and clears the offer. A focused check observed a successful resolution with the guest answer still on the device and no import RPC. Prevent overlapping actions and distinguish a skipped operation from a completed import so the offer stays available. [Actions](pages/stats.js#L58-L86) · [Import lifetime](utils/useProgressDashboard.js#L95-L108) · [Import coordinator](utils/accountProgress.js#L89-L99) · [Skipped callback](utils/progressWriteCoordinator.js#L41-L53)

### 6. A slow pending upload can block readable account history · Medium

The dashboard handles a rejected upload and can then read history, but it awaits the whole replay before requesting that history. With a queued answer and a slow or stalled write, Progress stays in its loading state and disables refresh and reset. A focused check held a mock upload response and observed that the readable dashboard RPC only ran after release. The prior test covers rejection, which reaches the catch block. Fetch the dashboard independently and refresh it after any replay that changes it. [Snapshot load](utils/accountProgress.js#L101-L111) · [Loading state](utils/useProgressDashboard.js#L48-L67) · [Controls and loading panel](pages/stats.js#L70-L118) · [Existing rejection test](tests/accountProgress.test.cjs#L18-L24)

### 7. AI Auto Cycle can advance past a failed save and lose its pending answers · Medium

When an AI round solves successfully but the cloud save fails, the finalizer returns `{ saved: false }` and sets the failed summary. The batch loop ignores the result and schedules the next round. The transition takes precedence over the failure and the next start clears the old summary. The AI buffer holds unsynced rows only in memory. If the failure persists until navigation away after the round or an account change, the retry surface and pending rows can both disappear. Keep the failed round visible and pause Auto Cycle on save failure. Preserve a retryable queue across navigation if persistence is part of the intended AI workflow. [Save result](pages/index.js#L436-L450) · [Cycle advance](pages/index.js#L1072-L1083) · [Transition precedence](utils/trainerPresentation.js#L35-L64) · [Next-round state](pages/index.js#L662-L665) · [Buffer lifecycle](utils/aiModeLogs.js#L239-L306) · [Account change](pages/index.js#L279-L296)

### 8. Trainer settings failures are silent · Medium

Both preference providers first apply settings in memory, then return an error when local storage or the account write fails. The Standard and Mixed setup handlers discard that result. A changed operation, difficulty, timer setting, or round size can appear applied for the current view and revert after reload with no explanation. Appearance already uses the returned error to report failed persistence. Surface an equivalent status near the trainer setup, including when an in-memory setting remains usable. [Standard controls](pages/index.js#L569-L582) · [Standard setting update](pages/index.js#L1191-L1225) · [Mixed setting update](pages/mixed.js#L834-L847) · [Standard provider](utils/accountPreferencesContext.js#L229-L245) · [Mixed provider](utils/mixedTrainerContext.js#L142-L157) · [Appearance feedback](components/CommandDesk.js#L158-L183)

### 9. Single-operation Mixed sessions are reported as Standard operation sessions · Low

Mixed allows starting with one enabled operation. A guest session records `kind: 'mixed'`, but the Mode column derives its value from the number of distinct operations and ignores the known session kind. A focused guest dashboard check observed `Addition` for a session explicitly recorded as `mixed`. Cloud log rows omit the trainer kind and the dashboard SQL uses the same heuristic. This also affects early exits with only one attempted operation. Retain the source trainer kind from guest storage through import and account writes, and use operation inference only for historical rows without it. [Mixed start and kind](pages/mixed.js#L486-L505) · [Guest mode inference](utils/progressDashboard.js#L331-L370) · [Cloud log row](utils/mixedTrainerRound.js#L446-L462) · [Cloud mode inference](supabase/migrations/20260418010000_enforce_exponent_cutover_and_90_day_retention.sql#L174-L207)

### 10. The calculator saves undefined real results as successful solves · Medium

The calculator checks the returned data type and display length but accepts non-finite numeric values. A focused call to the real solver with `log(0)` returned `kind: 'decimal'` and `-Infinity` in both result fields. The worker returns that object and the page saves it before showing success. Custom rows then contribute a solved attempt to account history. Reject non-finite results before formatting and persistence, and show a domain error. [Scalar check](utils/aiMath.js#L109-L116) · [Decimal result](utils/aiMath.js#L276-L286) · [Worker result](workers/aiCalculator.js#L1-L9) · [Custom save](pages/index.js#L1272-L1307) · [Progress aggregation](supabase/migrations/20260418010000_enforce_exponent_cutover_and_90_day_retention.sql#L108-L128)

### 11. Custom switches lack accessible names and the input-mode tabs lack tab keyboard behavior · Medium

The Mixed Right-to-left and Hide Timer switches and the Standard AI Auto Cycle switch have visible sibling labels, but the buttons contain only a decorative thumb and have no accessible name association. The Standard Manual/AI controls expose `tablist` and `tab` roles but omit arrow navigation and associated tab panels. These markup contracts affect keyboard and screen-reader operation. Associate each switch with its visible label and use an accessible selection control for the input mode or implement the complete tabs pattern. [Mixed switches](pages/mixed.js#L934-L961) · [Auto Cycle](pages/index.js#L1342-L1361) · [Mode tabs](pages/index.js#L1514-L1535) · [Switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/) · [Tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

### 12. Confirmed Back traversal can return to the page it was supposed to leave · Medium

The navigation guard increments its position only for intercepted `pushState` calls and uses the difference between these positions as the browser’s history offset. The native skip link can add a fragment entry outside that wrapper. The pinned router handles a null fragment state via `replaceState`, which stamps the same position on the extra entry. In a history model with an intervening duplicate-position entry, the production guard showed the confirmation, then used an offset that landed on a different entry and bounced back to the origin. The existing test uses one numbered entry per offset. Preserve browser entry identity across fragment changes and test multi-entry Back/Forward with fragment entries, including cancel and confirm. The history model exercised the guard, and device-specific behavior remains to be checked. [Skip link](components/SiteLayout.js#L479-L481) · [Traversal arithmetic](utils/roundNavigation.js#L6-L57) · [Existing history test](tests/roundNavigation.test.cjs#L4-L45) · [Fragment navigations](https://html.spec.whatwg.org/multipage/browsing-the-web.html#fragment-navigations) · [Pinned router](https://github.com/vercel/next.js/blob/v15.5.29/packages/next/src/shared/lib/router/router.ts)

### 13. Guest import repeatedly reads the whole history · Low

For each offered session, the import path calls `getGuestHistory`, which loads both stores with `getAll`, filters retained attempts, and sorts them. It filters and sorts again for the target session and triggers a retention pass after marking the session imported. With many retained sessions this revisits the same rows repeatedly, prolonging a workflow that also holds the import lock. This is a source-derived cost. Runtime impact was unmeasured. Read attempts for the claimed session through the existing `sessionId` index and prune once after the import job or on its next maintenance pass. [Import loop](utils/accountProgress.js#L74-L98) · [Index](utils/progressStorage.js#L43-L45) · [Full history read](utils/progressStorage.js#L182-L200) · [Import completion](utils/progressStorage.js#L315-L325)

### 14. Android discovery stops at the first plausible release · Medium

After the endpoint issue is resolved, the updater still reads only the first page of 20 releases and chooses the first stable Android tag with a manifest. An incompatible SDK, incomplete asset, or version at or below the installed version stops the search even if another compatible update exists. The November 14 audit reproduced this against the same published 1.0.5 archive with a mocked API 29 device. Its SDK-30 release prevented the manager from checking the following SDK-24 release. Follow pagination when needed and choose the highest compatible newer version with a valid manifest, preserving the native verification checks. [Prior audit, finding 18](CODEBASE_AUDIT.md#18-the-android-updater-stops-before-checking-a-compatible-release--medium) · [Release listing API](https://docs.github.com/en/rest/releases/releases#list-releases) · [Published source](https://github.com/solk3lly/mental-math-trainer/releases/expanded_assets/android-v1.0.5) (`utils/androidUpdates.js:1–3, 18–46, 117–135`)

### 15. Two tracked review scripts still expect old defects · Low

The trainer review script strips imports and supplies its own dependency map. It exits with `ReferenceError: useAccountProgressRound is not defined` before driving the current trainer. It also asserts that a guest round stays open and starts uploading under the new account after sign-in, which conflicts with the current ownership tests. The arithmetic review script verified 16,640 generated problems and then failed on `assert(aiMismatches > 0)` because the old decimal error was absent in its 100 sampled solves. These failures belong to the review scripts. Retire the historical repro scripts or adapt their fixtures and expectations to the current contracts. ## Manual acceptance after fixes

1. In a test account, delay the first of two resets from different devices and record an answer in the newest generation. It should survive the first response and sync. Start import during reset and confirm it completes or leaves a visible retry. While an upload is waiting, confirmed account history should still load.
2. In both trainers, let a guest checkpoint fail after one committed answer. Leave the round and confirm the committed answer remains visible and the session can be cleared or imported. Change a preference with storage denied and with an account save failure. The control should report failed persistence.
3. Run AI Auto Cycle through a failed save and confirm retry remains available. Check undefined real calculations and normal calculator expressions. Check switch names and mode selection with keyboard and assistive technology. Test multi-entry Back and Forward over a hash entry, with both confirm and cancel.
4. On a supported Android device using a test account, check updater discovery, a compatible release behind an incompatible one, in-place installation, and account preference and progress sync before and after a test reset on the intended schema.
